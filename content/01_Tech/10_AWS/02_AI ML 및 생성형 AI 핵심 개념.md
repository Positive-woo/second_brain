# AI·ML 및 생성형 AI 핵심 개념

목차: [[00_AWS 시험 학습 목차]] · 서비스 적용: [[01_AWS AI ML 서비스 비교]]

## 1. 기본 용어

| 용어 | 의미 | 시험에서의 연결 |
| --- | --- | --- |
| AI | 인간의 인지 능력과 유사한 작업을 수행하는 기술의 넓은 범주 | 인식·판단·생성 등을 포괄 |
| ML | 데이터에서 패턴을 학습해 예측·판단하는 AI 접근법 | 수요 예측, 분류, 추천 |
| 딥러닝 | 다층 신경망을 활용하는 ML 접근법 | 이미지·음성·언어 모델 |
| 생성형 AI | 학습한 패턴을 바탕으로 새로운 콘텐츠를 생성하는 AI | 텍스트·이미지·코드 생성 |
| FM(Foundation Model) | 광범위한 데이터로 사전 학습되어 여러 작업에 적용 가능한 모델 | Bedrock, JumpStart |
| LLM | 언어 처리·생성을 중심으로 하는 대규모 모델 | FM의 대표적인 유형 |
| 토큰 | 모델이 처리하는 텍스트 등의 단위. 단어와 일대일로 같지는 않음 | 입력·출력 비용, 문맥 길이 |
| 추론(Inference) | 학습된 모델에 입력을 주고 결과를 얻는 과정 | 예측, 분류, 답변 생성 |

AI ⊃ ML ⊃ 딥러닝의 포함 관계로 이해한다. 현대 생성형 AI는 주로 딥러닝 기반이지만 AI 전체가 생성형 AI인 것은 아니다.

## 2. 학습 방식

| 방식 | 핵심 | 사례 |
| --- | --- | --- |
| 지도 학습 | 정답 레이블이 있는 데이터로 학습 | 스팸 여부 분류, 주택 가격 예측 |
| 비지도 학습 | 정답 레이블 없이 데이터 구조 탐색 | 유사 고객 군집화 |
| 강화 학습 | 환경에서 행동하고 받은 보상을 바탕으로 정책 학습 | DeepRacer 주행 정책 |

**강화 학습의 네 가지 단서:** 에이전트 → 환경 관찰 → 행동 → 보상. ‘모든 추천 서비스는 강화 학습’처럼 서비스 목적과 알고리즘을 동일시하지 않는다.

## 3. 학습·추론·배포

- **학습:** 데이터로 모델 파라미터를 바꾸는 단계.
- **추론:** 학습된 모델을 사용해 입력에 대한 결과를 만드는 단계.
- **배포:** 모델을 애플리케이션에서 사용할 수 있도록 제공하는 과정. 실시간 엔드포인트뿐 아니라 배치 추론 구성도 가능하다.
- **미세 조정:** 사전 학습된 모델을 추가 데이터로 학습해 작업·스타일 등에 맞추는 것.

‘이미 학습된 모델을 사용한다’는 말은 대체로 추론을 뜻하며, 그 모델을 이용할 때마다 처음부터 학습하는 것은 아니다.

## 4. 프롬프트·RAG·미세 조정

| 접근 | 바꾸는 것 | 적합한 요구 | 주의점 |
| --- | --- | --- | --- |
| 프롬프트 엔지니어링 | 지시·예시·입력 문맥 | 답변 형식·역할·작업 안내 | 모델 가중치는 변경하지 않음 |
| RAG(검색 증강 생성) | 답변에 참고할 외부 검색 문맥 | 최신 사내 문서에 근거한 답변 | 검색 품질·문서 권한·근거 확인 필요 |
| 미세 조정 | 모델 파라미터 | 일관된 업무 패턴·스타일·특화 작업 | 학습 데이터·비용·평가 필요 |

### RAG의 기본 흐름

1. 사용자 질문과 관련된 문서를 검색한다.
2. 검색 결과를 질문과 함께 모델의 문맥으로 전달한다.
3. 모델이 제공된 근거를 활용해 답변을 생성한다.

RAG는 보통 모델 가중치를 바꾸지 않는다. 자료가 바뀔 때 모델을 재학습하기보다 문서·검색 인덱스를 갱신하는 방식이다. **환각을 줄이는 데 도움이 되지만 완전히 없애지는 않는다.**

### 미세 조정에 대한 오해

- 최신 사실을 계속 주입하는 데 항상 최선은 아니다. 최신 문서 참조가 핵심이면 RAG를 먼저 검토한다.
- 미세 조정한 모델도 사실 오류를 낼 수 있으므로 평가가 필요하다.
- Bedrock과 SageMaker AI 모두 해당 기능을 제공할 수 있으므로 서비스 선택은 지원 모델과 운영 요구사항을 함께 본다.

## 5. 목적별 AI API도 준비가 필요하다

| 예시 | 필요한 준비 |
| --- | --- |
| Translate로 번역 | 번역할 텍스트·언어 설정 |
| Textract로 문서 추출 | 지원되는 문서·이미지, 결과 처리 |
| Personalize로 추천 | 상호작용·아이템 등 데이터, 솔루션에 따른 학습·설정 |
| Lex로 예약 챗봇 | 의도(Intent), 수집할 정보(Slot), 대화·백엔드 처리 |

‘관리형 서비스’는 고객의 데이터 품질 관리·설정·권한 관리까지 없어지는 뜻이 아니다.

## 6. 시험에서 서비스 고르는 순서

1. **입력·출력을 찾는다.** 음성→글인가, 글→음성인가?
2. **핵심 작업을 정한다.** 추출·분석·검색·생성·학습 중 무엇인가?
3. **직접 개발할 범위를 읽는다.** 완성된 기능/API인가, 모델 운영 제어가 필요한가?
4. **보안·비용·지연·리전 등 조건을 확인한다.** 목적이 맞아도 제한을 충족해야 한다.
5. **오답을 제거한다.** 비슷한 이름보다 ‘하지 않는 일’을 설명한다.

## 7. 책임 있는 활용의 기본

- **환각:** 그럴듯하지만 사실과 다른 생성 결과. 근거 검증·검색·인간 검토를 함께 고려한다.
- **편향:** 데이터나 모델 때문에 특정 집단 등에 불공정한 결과가 생길 수 있다. 데이터·평가·운영 전체에서 점검한다.
- **접근 제어:** 사내 검색·RAG를 붙여도 사용자가 볼 수 없는 문서가 답변에 노출되면 안 된다.
- **개인정보:** 입력·학습·로그에 포함되는 민감정보와 보존·처리 정책을 확인한다.
- **공동 책임:** AWS가 관리하는 인프라와 고객이 관리해야 할 데이터·권한·사용 방식을 구분한다.

이 절은 입문 요약이다. 책임 있는 AI와 보안·거버넌스의 전체 시험 범위를 대신하지 않는다.

# 앞으로의 학습 로드맵

각 단계를 순서대로 진행한다. 작은 실습은 본인 기기와 허가된 로컬 네트워크에서만 한다.

## 1단계 - 서브넷, 서브넷 마스크, CIDR

**목표:** IP 주소에서 네트워크 부분과 기기 부분을 구분하고, 같은 네트워크인지 기초적으로 판단한다.

- 핵심 질문: `192.168.1.10/24`에서 `/24`는 무엇을 뜻할까? `192.168.1.20`은 같은 서브넷일까?
- 작은 실습(macOS): 시스템 설정의 네트워크 상세 정보에서 IP와 라우터 주소를 확인한다. 터미널에서 `ifconfig`로 인터페이스 주소를 찾아보고 숫자를 기록해 본다.
- 완료 체크: 사설 IP 세 범위를 말할 수 있다. `/24`가 네트워크 범위를 나타내는 표기임을 설명할 수 있다. 같은 서브넷 여부를 간단한 예시에서 판단할 수 있다.

## 2단계 - ARP

**목표:** 같은 LAN에서 IP 주소를 실제 링크 계층 전달 주소인 MAC 주소와 연결하는 과정을 이해한다.

- 핵심 질문: 같은 LAN의 기기로 보내는 패킷은 상대의 MAC 주소를 어떻게 알아낼까?
- 작은 실습(macOS): `arp -a`로 현재 ARP 캐시를 확인한다. 게이트웨이에 한 번 접속한 뒤 다시 확인해 항목 변화를 살펴본다.
- 완료 체크: IP 주소와 MAC 주소의 역할 차이를 설명한다. ARP가 주로 같은 링크에서 쓰인다는 점을 안다.

## 3단계 - DNS 심화

**목표:** 이름을 IP 주소로 바꾸는 기본 흐름과 캐시 개념을 이해한다.

- 핵심 질문: 브라우저가 도메인 이름을 받으면 연결 전에 무엇을 조회할까? 캐시가 있으면 어떤 점이 달라질까?
- 작은 실습(macOS): `nslookup example.com`으로 조회 결과를 관찰한다. 같은 이름을 다시 조회해 결과를 비교한다.
- 완료 체크: DNS가 IP를 찾는 역할임을 말할 수 있다. DNS가 NAT나 포트포워딩과 다른 역할임을 설명한다.

## 4단계 - 패킷과 TCP 3-way handshake

**목표:** 데이터가 패킷으로 나뉘어 전달되는 개념과 TCP 연결 시작 과정을 익힌다.

- 핵심 질문: TCP 통신은 데이터를 보내기 전에 왜 연결을 확인할까? SYN, SYN-ACK, ACK는 어떤 순서일까?
- 작은 실습(macOS): `ping`으로 목적지에 도달 가능한지 관찰한다. 응답 여부는 네트워크 정책에 따라 달라질 수 있음을 함께 기록한다.
- 완료 체크: 패킷과 전체 데이터의 관계를 설명한다. 3-way handshake 순서를 말할 수 있다.

## 5단계 - 포트 복습과 통신 흐름

**목표:** 출발지·목적지 IP와 포트를 읽고 클라이언트와 서버의 역할을 구분한다.

- 핵심 질문: `내PC:55000 -> 서버:443`에서 각 포트는 누구의 것인가? 서버 응답의 목적지 포트는 무엇인가?
- 작은 실습(macOS): 브라우저로 웹사이트에 접속한 뒤 `netstat -an`의 연결 목록에서 로컬·외부 주소와 포트를 살펴본다.
- 완료 체크: 클라이언트의 임시 출발지 포트와 서버 서비스 포트를 구분한다. 포트는 TCP/UDP와 함께 확인한다.

## 6단계 - HTTP, HTTPS, TLS

**목표:** 웹 요청·응답의 큰 흐름과 HTTPS가 TLS로 통신을 보호하는 이유를 이해한다.

- 핵심 질문: HTTP 요청과 응답은 무엇이며, HTTPS는 어떤 보호를 더할까?
- 작은 실습(macOS): 브라우저 주소창에서 자물쇠나 사이트 정보와 인증서 발급 대상, 유효 기간을 확인한다.
- 완료 체크: HTTP와 HTTPS의 차이를 설명한다. TLS가 통신 내용을 암호화하고 서버 신원을 확인하는 데 쓰인다는 점을 말할 수 있다.

## 7단계 - 방화벽, IDS, IPS

**목표:** 네트워크 접근을 제한하는 장치와 침입 탐지·차단의 차이를 익힌다.

- 핵심 질문: 방화벽 규칙은 무엇을 허용하거나 막을까? IDS와 IPS의 차이는 무엇일까?
- 작은 실습(macOS): 시스템 설정의 네트워크 방화벽 상태를 확인한다. 설정을 바꾸기 전 현재 상태와 의미를 기록한다.
- 완료 체크: 방화벽은 규칙에 따라 통신을 허용·차단한다는 점을 말할 수 있다. IDS는 탐지·알림, IPS는 탐지 후 차단까지 수행할 수 있음을 구분한다.

## 8단계 - DDoS의 L3, L4, L7 구분

**목표:** 네트워크 계층, 전송 계층, 응용 계층에서 서비스가 받는 부담을 쉬운 수준으로 구분한다.

- 핵심 질문: 회선 대역폭, 패킷 처리, 웹 요청 처리 중 무엇이 병목인가?
- 작은 실습: 실습 환경이나 허가된 자료에서 트래픽 그래프를 읽고 BPS와 PPS를 각각 관찰한다. 실제 공격 트래픽을 만들거나 외부 대상으로 시험하지 않는다.
- 완료 체크: L3/L4/L7이라는 분류가 서로 다른 네트워크 계층을 가리킴을 안다. 공격 유형에 따라 방어 지점이 달라질 수 있음을 설명한다.

## 9단계 - 로그 관찰과 안전한 실습

**목표:** 시스템이 남긴 연결·오류 정보를 관찰하고, 정상 동작과 문제 상황을 비교한다.

- 핵심 질문: 연결이 실패했을 때 주소 오류, 이름 조회 실패, 서비스 응답 없음 중 무엇인지 어떻게 구분할까?
- 작은 실습(macOS): `netstat -an`과 `arp -a` 결과를 시간과 함께 기록한다. 본인 컴퓨터에서 브라우저 접속 전후의 연결 차이를 비교한다.
- 완료 체크: 관찰 시각과 상황을 같이 기록한다. 로그만으로 원인을 단정하지 않고 가능한 원인을 나눠 본다.

## 10단계 - 기타 보안 기초

**목표:** 계정, 업데이트, 최소 권한, 백업, 피싱 대응 같은 일상 보안 습관을 익힌다.

- 핵심 질문: 계정이 노출되거나 기기가 분실되어도 피해를 줄이려면 무엇을 준비해야 할까?
- 작은 실습: 중요 계정의 다중 인증 여부와 기기 업데이트 상태를 확인한다. 복구 방법과 백업 위치를 점검한다.
- 완료 체크: 고유한 비밀번호와 다중 인증을 사용한다. 업데이트와 백업의 목적을 설명하고, 의심스러운 링크를 확인하는 습관을 가진다.
